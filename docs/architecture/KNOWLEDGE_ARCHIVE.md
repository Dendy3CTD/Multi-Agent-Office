# MAO — KNOWLEDGE ARCHIVE

Постоянная память офиса: SQLite (оперативное состояние), Obsidian
(долговременный архив), резервное копирование. Компонент: C14 Knowledge
Manager (`packages/archive`, пустой → заполнить). Согласуется с
`docs/OBSIDIAN-ARCHIVE.md` (спецификация vault сохраняется).

## 1. Слои хранения (кратко)

| Слой | Технология | Роль |
| --- | --- | --- |
| Оперативное состояние | SQLite `~/.local/share/open-agent-office/office.db` | источник истины задач/событий |
| Финансовый ledger | JSONL C08 (существующий) | неизменяемый учёт расходов |
| Архив | Markdown в Obsidian vault | долговременная память и база знаний |
| Код/артефакты | ФС + Git | источник истины для результатов |

## 2. SQLite event store

- Все события шины C06 сначала записываются в таблицу `events`
  (транзакционно, монотонный id, payload без секретов — redaction на
  границе публикации, как уже делает C15 для событий Runtime).
- Таблицы доменных сущностей (DATA_MODEL.md) обновляются в той же
  транзакции, что и событие, где применимо.
- WAL-режим; периодический `PRAGMA wal_checkpoint`; файл вне Git.

## 3. Outbox и экспорт в Obsidian

Правило: **ни одно событие не экспортируется, пока не зафиксировано
durable в SQLite** (принцип 12 AGENTS.md, docs/OBSIDIAN-ARCHIVE.md).

1. Экспортёр читает `outbox` (status=pending, упорядоченно).
2. Формирует Markdown по шаблонам категорий; имя файла — стабильное от
  eventId/entityId (`tasks/<taskId>.md` обновляется, `events/<eventId>.md`
  создаётся один раз).
3. Запись атомарная: временный файл + rename; только после fsync/rename
  outbox переводится в `exported`.
4. Повторный экспорт того же события — идемпотентен (перезапись того же
  файла тем же содержимым); сбой → retry с backoff, `failed` после N
  попыток + событие тревоги.

## 4. Структура vault (по docs/OBSIDIAN-ARCHIVE.md)

База: `~/Документы/Obsidian Vault/09 - 🗃️ АРХИВ/Open Agent Office/`.
Документация проекта-разработки: `02 - 🚀 ПРОЕКТЫ/Open Agent Office/`.
Категории: Projects, Tasks, Employees, Decisions, Actions, Reports,
Artifacts, Daily Logs, Events, Skills.

- Формат: стандартный Markdown, YAML-фронтматтер (id, тип, статус, даты,
  связи), `[[wikilinks]]` между объектами (задача ↔ подзадачи ↔ сотрудники
  ↔ артефакты ↔ решения).
- Проектные страницы содержат историю выполнения (ссылки на задачи) и
  ссылку на Project Memory файла проекта.
- Экспортёр пишет только в выделенные директории OAO; пользовательские
  заметки вне их не изменяются (принцип 11 AGENTS.md).

## 5. Что хранится (соответствие требованиям)

| Объект | Файл(ы) | Источник |
| --- | --- | --- |
| Проекты | `Projects/<projectId>.md` | events project_* |
| Задачи/подзадачи | `Tasks/<taskId>.md` (+ секции подзадач) | events task_*/subtask_* |
| Сотрудники | `Employees/<employeeId>.md` | C01 + события |
| Решения | `Decisions/<decisionId>.md` | plan_revised, model_escalated, director-решения |
| Действия | `Actions/<executionId>.md` | события исполнения (без секретов) |
| Отчёты | `Reports/<date>-<taskId>.md` | итоги приёмки, validation |
| Артефакты | `Artifacts/<artifactId>.md` (ссылка на ФС-путь, хэш) | artifact_registered |
| История выполнения | секции в Tasks/Projects | агрегация событий |
| События | `Events/<yyyy-mm>/<eventId>.md` | outbox |
| Связи | wikilinks + фронтматтер `related:` | экспортёр |

## 6. Поиск, экспорт, резервное копирование

- **Поиск**: SQLite-индекс (FTS5 по title/brief/тегам + поля связей) с
  выдачей путей Markdown; API `GET /v1/archive/search`. Obsidian
  остаётся основным интерфейсом поиска для человека.
- **Экспорт**: архив уже является экспортом (Markdown); дополнительно —
  `GET /v1/archive/export` собирает плоский набор файлов по фильтру.
- **Резервное копирование**: снапшот `office.db` (SQLite backup API) +
  копирование директории OAO vault + JSONL-журналы C08; команда
  `archive:backup`; расписание — внешнее (cron/systemd), не в ядре.
- **Восстановление**: из снапшота БД + журналов; vault пересобирается
  из outbox/events (экспорт идемпотентен), либо копируется из бэкапа.
  Проверка целостности: сверка хэшей манифестов артефактов и счётчиков
  событий; отчёт `archive_integrity`.

## 7. Приватность

- Запрещено архивировать: credentials, API keys, пароли, cookies,
  приватные ключи (docs/OBSIDIAN-ARCHIVE.md). Redaction на границе
  публикации событий + повторная проверка экспортёра (список паттернов
  как в C15, единый модуль redaction в `packages/shared`).
- Настраиваемые исключения файлов/директорий (конфигурация проекта).
- Финансовые суммы (RUB/USD) — не секреты; тексты prompt/ответов
  архивируются по умолчанию в виде ссылок на сессию и выдержек без
  чувствительных данных (D-07, режим метаданных). Полные тексты — только
  в **специальном режиме** (`fullTextMode`, включается явной настройкой
  проекта/задачи) и всегда после очистки секретов (единый модуль redaction
  из `packages/shared` + повторная проверка экспортёра). Включение режима
  фиксируется событием; режим не распространяется ретроактивно на прошлые
  записи.

## 8. Связь со статистикой

C14 материализует `ModelStats` (DATA_MODEL.md) из событий usage и
вердиктов валидации; используется C05 (оценка планов) и C07 (выбор
моделей). Финансовые сводки читаются из журналов C08 в режиме
только-чтение (писатель — только C08).
